# PCOSina Nutritionist Meal-Plan Evaluation Prep Guide

Prepared for the Registered Nutritionist-Dietitian meal-plan evaluation meeting.

## 1. Purpose Of This Guide

This guide prepares the team to explain how PCOSina generated the representative meal plans, what data and formulas were used, what the Registered Nutritionist-Dietitian is being asked to evaluate, and how to answer likely questions clearly.

Use this guide as a speaking and Q&A reference. Do not present PCOSina as a clinical treatment system. Present it as a wellness decision-support application that generates software-based meal-plan suggestions for expert review.

## 2. One-Minute Opening Statement

Sir, PCOSina is an offline-first Filipino meal-planning application for individuals managing PCOS. It does not diagnose or treat PCOS. For this evaluation, the researchers respectfully request your review of representative meal plans generated by the system and your professional assessment of whether they are nutritionally appropriate, practical, culturally relevant, and reasonable within the stated user profile and weekly budget.

The system generates plans by taking user profile inputs such as age, weight, height, activity level, goal, symptoms, allergies, dietary restrictions, pantry items, cooking time, variety preference, and weekly budget. It then computes calorie and macro targets, removes recipes that violate hard rules such as allergies or dietary restrictions, and selects a seven-day meal plan from the remaining recipe catalog using deterministic optimization.

The evaluation is not intended to certify PCOSina as a medical device. The request is for professional feedback on whether the generated meal plans are acceptable as software-generated wellness meal-plan outputs, and what improvements should be made.

## 3. What To Send The Registered Nutritionist-Dietitian

Send a packet that is easy to evaluate. For each scenario, include:

- User profile: age, sex assumption if applicable, height, weight, BMI if available, goal, symptoms, activity level, restrictions, allergies, budget, cooking-time limit, pantry items.
- Seven-day meal plan: breakfast, lunch, dinner for each day.
- Nutrition per meal: calories, protein, carbohydrates, fat if available, fiber, and any sodium/sugar values if available.
- Weekly averages: average calories/day, protein/day, carbohydrates/day, fiber/day, and estimated weekly cost.
- Unique recipe list: every unique recipe appearing in the plan, with ingredient list.
- Notes: whether the plan respects restrictions/allergies/budget, and any known limitations.
- Evaluation form: nutritionally appropriate, budget-appropriate, overall acceptable, comments/recommendations.

Important: If the expert asks how many recipes are included per plan, answer by counting unique recipes, not just meal slots. A seven-day plan has 21 meal slots, but some recipes repeat.

## 4. What The Expert Is Evaluating

The Registered Nutritionist-Dietitian is not being asked to validate the code. The expert is evaluating the meal outputs from a nutrition perspective:

- Are the meals nutritionally appropriate for the given profile?
- Are calories and macros reasonable for the stated goal?
- Is fiber adequate or reasonable?
- Are meal choices practical for everyday Filipino users?
- Are the meals culturally relevant?
- Are restrictions and allergies respected?
- Is the estimated cost reasonable within the weekly budget?
- Are there meals that should be replaced, reduced, or flagged?
- Are there nutrition concerns, such as too much repetition, too much pork, too little vegetables, very high calories in a meal, or unrealistic meal combinations?

## 6. How PCOSina Generates A Meal Plan

### Step 1: Collect User Profile

The system uses:

- age
- weight
- height
- target weight
- activity level
- goal: General Health, Weight Loss, or Symptom Management
- PCOS symptoms
- dietary restrictions
- allergies
- weekly budget
- maximum cooking time
- variety preference
- pantry preference
- available pantry items

### Step 2: Compute Health And Nutrition Targets

PCOSina computes body and nutrition targets using deterministic formulas.

BMI:

```text
BMI = weightKg / (heightCm / 100)^2
```

BMR uses the female Mifflin-St Jeor equation:

```text
BMR = (10 * weightKg) + (6.25 * heightCm) - (5 * age) - 161
```

TDEE:

```text
TDEE = BMR * activity multiplier
```

Activity multipliers:

| Activity Level | Multiplier |
| --- | ---: |
| Sedentary | 1.2 |
| Lightly Active | 1.375 |
| Moderately Active | 1.55 |
| Very Active | 1.725 |

Goal adjustment:

| Goal | Adjustment |
| --- | ---: |
| Weight Loss | -500 kcal/day |
| General Health | 0 kcal/day |
| Symptom Management | 0 kcal/day, then symptom-based nutrition nudges may apply |

Macro ratio policy:

| System profile state | Protein | Carbohydrate | Fat |
| --- | ---: | ---: | ---: |
| Default current planning profile | 25% | 40% | 35% |
| Backend-supported stricter profile, if configured | 28-30% | 30-35% | 37-40% |

Important note for the meeting: the current user-facing evaluation scenarios do not require the expert to review an insulin-resistance input. The backend still has a macro-ratio policy that can support stricter profiles, but for the current meal-plan evaluation, explain the macro targets as a system planning policy. The default planning split is approximately 25% protein, 40% carbohydrates, and 35% fat.

The 40% carbohydrate target is intentionally lower than the broad Acceptable Macronutrient Distribution Range commonly cited for general populations. It is used as a planning target for PCOS-oriented wellness support because the system prioritizes controlled calories, adequate protein, fiber, and steadier carbohydrate patterns. This is not the same as a glycemic-index calculation, and it is one reason expert review is needed.

Macro conversion:

```text
proteinGrams = targetCalories * proteinRatio / 4
carbGrams = targetCalories * carbRatio / 4
fatGrams = targetCalories * fatRatio / 9
```

Symptom Management can add deterministic nudges. For example, the system favors higher fiber, steadier carbohydrates, lower sugar pressure, or higher protein depending on the symptom tags. These are software rules and should be evaluated by the Registered Nutritionist-Dietitian.

### Step 3: Apply Hard Safety Filters

Before optimization, PCOSina removes recipes that violate hard constraints.

Examples:

- allergy conflicts
- dietary restrictions such as No Pork, No Beef, Vegetarian, Pescatarian, Lactose Intolerant
- meal-type incompatibility
- configured budget cap when applicable
- cooking-time limits when applicable

This means unsafe recipes should not be selected intentionally. If the expert finds a restriction violation in a sample plan, treat it as an important validation finding.

### Step 4: Rank Candidate Recipes

The system scores remaining recipes using factors such as:

- protein
- fiber
- calorie closeness
- estimated cost
- pantry overlap
- symptom/goal fit
- preparation time

Simplified Stage 1 scoring idea:

```text
Score increases with protein, fiber, pantry match, and goal/symptom fit.
Score decreases with high cost, far-from-target calories, and preparation burden.
```

### Step 5: Optimize The Weekly Plan

The planner then selects meals for 7 days and 3 meal slots per day. That gives 21 meal slots.

The optimizer tries to balance:

- calorie target
- protein target
- carbohydrate target
- fat target
- fiber target
- weekly budget
- recipe repetition
- meal variety
- preparation time
- pantry use

The system uses OR-Tools CP-SAT for the final 0-1 weekly assignment model. For expert discussion, this can be explained simply as a mathematical optimizer that chooses the best combination of recipes after unsafe options are removed.

## 7. How To Explain The Nutrition Facts

Use this answer:

The nutrition values shown in the meal plans come from the PCOSina recipe catalog. Each recipe record includes calories, protein, carbohydrates, fat where available, fiber, meal type, ingredient list, estimated preparation time, and tags. The system uses these stored values to compute per-meal totals, daily totals, and weekly averages.

The recipe catalog was structured using recipe-level nutrition entries and ingredient metadata stored in the project dataset. Where nutrition details are incomplete, the limitation should be disclosed. The system also keeps the values traceable through the exported recipe inventory, so the expert can review which recipe record produced each meal's nutrition figures.

However, the dataset should not be presented as a clinical nutrition database or a substitute for Registered Nutritionist-Dietitian review. The expert evaluation is requested specifically to verify whether the computed values and resulting meal plans are reasonable, acceptable, and aligned with nutrition practice.

If asked whether the nutrition facts are credible:

The values are structured and traceable within the PCOSina recipe catalog and validation exports. They are not manually invented inside the evaluation form. Each selected meal points back to a recipe record with calories, macros, fiber, ingredients, and tags. The team can show the recipe inventory export and formula documents used by the system. The professional evaluation is intended to strengthen credibility by identifying corrections, concerns, or approval from a Registered Nutritionist-Dietitian.

If asked how the nutrition values were entered into the system:

The values were stored per recipe in the application's recipe dataset and then exported into the thesis validation inventory. During meal-plan generation, the planner reads those stored recipe values instead of asking the user or the researchers to manually compute every meal in the appendix. For thesis reporting, the team should show the recipe inventory export and accept corrections if the expert identifies unrealistic or incomplete values.

If asked what sources support the nutrition approach:

The system's nutrition approach is supported by a combination of internal system evidence and external nutrition references. Internally, PCOSina uses the recipe inventory, formula documentation, and deterministic planner rules. Externally, the discussion may cite the 2023 International Evidence-Based Guideline for PCOS for lifestyle relevance, DOST-FNRI Pinggang Pinoy for Filipino food-group framing, and general dietary guidance for balanced dietary patterns. The actual approval of the generated sample plans still depends on the expert's professional review.

## 8. How To Explain Filipino Cultural Relevance

Use this answer:

The meal catalog is Filipino-focused because it includes Filipino dishes, Filipino cooking patterns, and locally common ingredients. Examples include adobo, bistek, ginataan, monggo, malunggay, pechay, sayote, kangkong, okra, bangus, tuna, rice, red rice, brown rice, calamansi, vinegar, soy sauce, garlic, onion, and ginger.

The structure also follows the idea of Filipino meal practicality: rice or staple carbohydrate, protein source, vegetables or fiber-rich ingredients, and familiar flavoring ingredients. This aligns with the spirit of Pinggang Pinoy, which uses food groups and meal balance for Filipino eating patterns.

If asked whether there is a specific "CIT" or cultural formula:

There is no separate clinical formula called CIT in the current implementation. Cultural relevance is handled through catalog design and recipe/ingredient tagging. In practical terms, the system uses a Filipino-focused recipe catalog, Filipino ingredient terms and synonyms, local pantry items, and price rules for common Philippine ingredients. The evaluation can describe this as catalog-based cultural localization or Filipino recipe-and-ingredient tagging, rather than a medical formula.

Important limitation: Filipino cultural relevance does not automatically mean every generated plan is nutritionally ideal. That is why the Registered Nutritionist-Dietitian is evaluating the outputs.

## 9. How To Explain PCOS Relevance

Use this answer:

PCOSina does not claim to cure or treat PCOS. It supports wellness meal planning by prioritizing nutrition factors commonly relevant to PCOS management, such as weight management, adequate protein, fiber-rich foods, controlled calories, steadier carbohydrate choices, and reduced sugar pressure when symptom management is selected.

The 2023 international PCOS guideline supports healthy lifestyle as a central part of PCOS care, but it does not require one universal diet for all PCOS patients. Because of that, PCOSina does not force a single fixed PCOS diet. Instead, it personalizes meal planning based on profile, goals, symptoms, restrictions, and budget, then requests professional evaluation of whether the outputs are appropriate.

## 10. Known Sample-Plan Red Flags To Prepare For

Be ready for the expert to notice issues. Do not argue with the expert. Treat these as validation findings.

### Scenario 7: Vegetarian

Potential issue:

- The sample includes `Tinutungan na Dinuguan`, which is not vegetarian.
- It may also include other recipe names that need ingredient verification.

Best answer:

Thank you for pointing that out. If a vegetarian scenario includes a meat-based dish, that should be treated as a validation finding and documented as a recipe-tagging or restriction-filtering issue. The correct system behavior should exclude meat or seafood from vegetarian meal plans. This expert feedback should be used to improve the recipe tags, regenerate the plan, and update the validation discussion.

### Scenario 9: No Beef

Potential issue:

- The sample includes `Bistek Tagalog (Filipino Beef Steak)` even though the user has a No Beef restriction.

Best answer:

That should be flagged. A No Beef profile should not include Bistek Tagalog. If this appears in the evaluated output, it means either the scenario export, recipe tagging, or restriction filtering needs correction. It should be documented as an expert-identified issue and regenerated or corrected before final inclusion if required.

### Scenario 10: Repeated Pork/High-Protein Meat Meals

Potential issue:

- Several breakfasts are pork-heavy or high-calorie, such as pork barbecue or bacon/chicken adobo.
- Fiber can be uneven by meal, with some meals showing 0g fiber.

Best answer:

The optimizer may select high-protein recipes because the profile is very active and the system is prioritizing protein and energy needs. However, if the expert finds the pork frequency, saturated-fat concern, or low-fiber meal distribution inappropriate, that should be treated as a nutrition recommendation. The system can improve by adding stronger limits for pork frequency, saturated-fat proxy tags, and vegetable distribution per meal.

### High Lentil/Monggo Repetition

Potential issue:

- Some plans repeat lentil or monggo bowls many times.

Best answer:

The repetition happens because the optimizer is balancing cost, fiber, protein, calorie targets, and constraints. Lentils and monggo score well because they are affordable, fiber-rich, and protein-supportive. However, too much repetition can reduce acceptability and variety. The app has a swap mechanism and variety preference setting, and the planner can also be improved by strengthening variety constraints or expanding the recipe catalog.

### Budget Much Lower Than User Budget

Potential issue:

- Example: weekly budget is PHP 5,000 but estimated plan cost is only PHP 1,430.

Best answer:

The budget is treated as a ceiling, not a spending target. If the system can generate a nutritionally acceptable plan below the budget, it may do so. However, if the expert thinks the low cost sacrifices food quality, portion realism, or variety, that feedback should be documented. Future versions can add a budget-utilization target or quality floor, not just a budget ceiling.

### Some Meals Have 0g Fiber

Potential issue:

- Some meat-heavy meals show 0g fiber.

Best answer:

The optimizer evaluates the daily and weekly pattern, not only each single meal. A meal with low fiber may still appear if the full day meets the fiber target through other meals. However, if the expert recommends minimum vegetables or fiber per meal, that can be added as a future constraint or scoring rule.

## 11. Likely Expert Questions And Best Answers

### Q1. Where did these meals come from?

The meals come from the PCOSina structured recipe catalog. The catalog contains recipe identities, meal types, ingredient lists, calories, protein, carbohydrates, fats where available, fiber, preparation time, and tags such as high fiber, high protein, vegan, pescatarian, contains meat, contains seafood, or contains dairy. The system selects from this catalog based on the user's profile and constraints.

Follow-up answer:

The source can be traced in the recipe inventory export at `docs/thesis_validation/03_ACTUAL_SYSTEM_DATA_EXPORTS/recipe_inventory.csv`. For the evaluation appendix, each scenario should also include a unique recipe list with ingredients so the expert can review the actual food materials, not only the recipe names.

### Q2. Where did the nutrition facts come from?

The nutrition facts are stored in the PCOSina recipe dataset and exported in the recipe inventory. These values are used by the system to compute meal totals and weekly averages. The values are presented for professional review, not as independently clinically certified figures. If the expert recommends corrections, those corrections should be applied to the recipe data.

Follow-up answer:

The values are credible in the sense that they are structured, traceable, and consistently used by the software. They should still be professionally validated. The review is meant to identify whether any recipe value appears unrealistic, incomplete, or needing correction.

### Q3. How did you compute the user's calorie target?

The system uses the female Mifflin-St Jeor equation to estimate BMR, multiplies it by an activity factor to estimate TDEE, then applies a goal adjustment. For weight loss, the system subtracts 500 kcal/day. For symptom management, the base calories may be maintained while the system applies nutrition preference nudges such as higher fiber, steadier carbohydrates, lower sugar pressure, or higher protein depending on symptoms.

### Q4. How did you compute protein, carbohydrate, and fat targets?

For the current evaluation scenarios, explain this as a backend planning policy, not as a user-entered insulin-resistance input. The default macro planning split is approximately 25% protein, 40% carbohydrates, and 35% fat. The system converts calories to grams using 4 kcal/g for protein, 4 kcal/g for carbohydrates, and 9 kcal/g for fat.

Follow-up answer:

The 40% carbohydrate target is intentionally lower than the broad 45-65% carbohydrate range often cited for general adults. PCOSina uses it as a planning target because the app is designed for PCOS-oriented wellness support, where controlled calories, adequate protein, fiber-rich foods, and steadier carbohydrate patterns are prioritized. This does not mean that 40% is the only correct value for every PCOS patient; it is a software target that should be reviewed by the expert.

### Q5. Why are some plans high in protein?

Protein is prioritized because it helps meal satiety and supports weight-management goals. Some symptoms, such as hair loss, also add a protein target bonus in the system. However, the final appropriateness of protein levels should be reviewed by the Registered Nutritionist-Dietitian, especially for users with kidney disease or other conditions not captured in the profile.

### Q6. Why are lentils or monggo repeated?

Lentils and monggo often score well because they are affordable, fiber-rich, and protein-supportive. They also fit many restrictions and budget-conscious scenarios. But if the repetition is too high, that is a valid nutrition and usability concern. The plan can be swapped, regenerated with higher variety, or improved through stricter repetition limits.

### Q7. Why are some meals not obviously PCOS-specific?

PCOSina does not require every recipe to be a special PCOS recipe. Instead, it tries to build a full weekly pattern that fits calorie, macro, fiber, budget, allergy, and restriction constraints. A familiar Filipino dish may be included if it fits the overall plan. The expert can flag any dish that should be limited, modified, or paired with vegetables.

### Q8. Are these meals really Filipino and culturally relevant?

Yes, the catalog includes many Filipino dishes and local ingredients. The plan uses familiar foods such as rice, adobo-style dishes, monggo, malunggay, pechay, kangkong, sayote, kalabasa, bangus, tuna, calamansi, vinegar, soy sauce, garlic, onion, and ginger. It is Filipino-focused, but the final judgment of practicality and acceptability comes from the Registered Nutritionist-Dietitian.

Follow-up answer:

The cultural relevance method is catalog-based. PCOSina uses Filipino recipes, Filipino ingredient names and synonyms, and local pantry/cost assumptions. It does not use a separate clinical formula called CIT in the current implementation.

### Q9. Why is the plan sometimes below the stated budget?

The budget is treated as a maximum limit, not a required spending amount. If the system finds a plan below budget while meeting other targets, it may select it. The expert may recommend using more of the budget to improve variety, fruits, vegetables, or protein quality.

### Q10. How do you know the plan is within budget?

The system uses a price catalog and cost-estimation rules to estimate recipe cost, then aggregates the selected meals across the week. The estimate is meant to support planning, not guarantee exact market prices. Prices can vary by location, season, serving size, and store.

### Q11. What happens if no safe plan can be generated?

The system returns a structured no-safe-plan response instead of forcing an unsafe meal plan. That can happen if the budget is too low, allergies and restrictions remove too many recipes, or the remaining recipes cannot meet the required constraints.

### Q12. Can the user replace meals?

Yes. The application can support meal swapping. Swaps should still respect active constraints such as allergies, restrictions, repeat limits, and budget. If the expert recommends replacing specific meals, those can be documented as professional recommendations.

### Q13. Are fruits included?

Some recipe records may include fruit or fruit-like ingredients such as banana or saba, but the sample plans may not consistently include fruits. If the expert recommends a daily fruit component or more explicit Pinggang Pinoy alignment, this is a valid improvement item.

### Q14. Do you account for sodium and sugar?

The system has objective terms for sodium and sugar when values are available. However, the recipe dataset may not have complete sodium and sugar values for every recipe. This is a limitation. The expert can recommend adding more complete micronutrient, sodium, and sugar data.

### Q15. Do you account for glycemic index or glycemic load?

Not directly as a complete glycemic-index or glycemic-load database. PCOSina currently uses practical proxies: a lower default carbohydrate planning ratio of about 40%, fiber preference, lower sugar pressure when data is available, and preference for steadier carbohydrate patterns. These help guide the plan, but they are not the same as calculating glycemic index or glycemic load.

Follow-up answer:

If glycemic index or glycemic load is important for the expert evaluation, that should be documented as a recommendation. A future version can add validated GI/GL fields per ingredient or recipe, but the current evaluation should not claim full GI/GL computation.

### Q16. Why do some meals show very high calories?

The optimizer may choose a higher-calorie meal if the daily total and weekly targets remain acceptable, especially for active users. However, if a single meal is too large or impractical, that should be documented as expert feedback. The system can be improved by adding stricter per-meal calorie bounds.

### Q17. Is this safe for all PCOS patients?

No. PCOSina is not a medical device and does not replace individualized diet counseling. Users with pregnancy, diabetes, kidney disease, hypertension, eating disorders, medication-related nutrition needs, or other clinical conditions should consult a physician or Registered Nutritionist-Dietitian.

### Q18. What standard did you use for PCOS meal planning?

The system uses general healthy lifestyle and nutrition principles, not a single prescriptive PCOS diet. The 2023 International Evidence-Based Guideline for PCOS supports healthy lifestyle as central to PCOS management but does not prescribe one universal diet. For Filipino food balance, the discussion references DOST-FNRI Pinggang Pinoy as a local food-group guide.

### Q19. Why do some vegetarian or no-beef plans show meat/beef dishes?

If that appears, it should be treated as an error or validation finding in the exported sample plan. The intended system behavior is to filter out recipes that violate dietary restrictions. The expert's finding will be documented and used to correct recipe tags, strengthen filters, or regenerate the plan.

### Q20. What exactly is requested from the Registered Nutritionist-Dietitian?

The requested output is your professional judgment on each representative plan: whether it is nutritionally appropriate, appropriate within the stated budget, and overall acceptable. Comments are also requested on meals that should be replaced, modified, reduced, or improved, and on the criteria or standards used in the evaluation.

## 15. Best Answers To Difficult Questions

### If asked: Are you claiming these plans are clinically approved?

No. The researchers are not claiming clinical approval before expert review. This evaluation is part of the validation process. The requested professional assessment is whether the outputs are acceptable and what improvements are needed.

### If asked: Why should I trust the nutrition numbers?

The nutrition numbers are structured, traceable, and used consistently by the system. They come from recipe records in the PCOSina dataset and are exported in the recipe inventory used for thesis validation. The system uses those stored recipe values to compute the per-meal and weekly summaries.

They are not being treated as unquestionable. The reason for this evaluation is to let a Registered Nutritionist-Dietitian review whether the values and meal outputs are reasonable. If the expert identifies unrealistic values, incomplete nutrient data, or meal issues, those will be documented as corrections or recommendations.

### If asked: Why did the system choose this meal?

The system chooses meals based on profile fit. It considers calories, protein, carbohydrates, fiber, cost, pantry overlap, restrictions, allergies, cooking time, and variety. A meal may be selected because it helps the weekly plan meet targets or stay within budget.

### If asked: Why is the plan not perfectly balanced every meal?

The optimizer balances the daily and weekly pattern. Some individual meals may be higher or lower in certain nutrients, but the system tries to balance the full day and full week. If per-meal balance is important, that can be added as a stricter future rule.

### If asked: Why does a plan include meat-heavy dishes?

The optimizer may select them when they help meet protein targets and budget constraints. However, if the expert recommends reducing pork, processed meat, or saturated-fat-heavy dishes, that will be documented as an expert recommendation.

### If asked: How will the recommendations be used?

The recommendations will be used to improve the discussion, identify recipe or filter issues, revise sample plans if needed, and add recommendations for future system enhancement. The feedback will be cited as expert validation evidence.
